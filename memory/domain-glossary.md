# Domain Glossary

Definitions of key terms used throughout the codebase, documentation, and team communication. When in doubt about terminology, refer to this file.

## Core Entities

### Prompt

The central entity. A prompt is a reusable AI instruction template that users browse, preview, and unlock. A prompt has a title, description, content (the actual prompt text), category, tags, type, and a status that tracks its lifecycle.

**Database model:** `Prompt`

### PromptDraft

A draft version of a prompt generated by an AI agent. Drafts are always linked to an AgentRun. A draft may or may not be linked to an existing Prompt -- new drafts create new prompts; revision drafts link to the prompt being improved.

**Database model:** `PromptDraft`

### PromptVersion

An immutable snapshot of a prompt's content at a specific point in time. Every time a published prompt's content is changed, a new version is created. Versions are numbered sequentially (1, 2, 3, ...).

**Database model:** `PromptVersion`

### Preview

A sample of the prompt's output shown to users before they unlock. Previews demonstrate the value of the prompt without giving away the full content. A prompt can have multiple previews (e.g., different use cases).

**Database model:** `PromptPreview`

### Category

A top-level classification for prompts. Categories are admin-managed and have a name, slug, description, optional icon, and sort order. Examples: Writing, Code, Marketing, Education.

**Database model:** `Category`

### Tag

A fine-grained label for discoverability. Tags are more flexible than categories -- a prompt belongs to one category but can have many tags. Tags have a name and slug.

**Database model:** `Tag`

## Events and Actions

### Unlock Event

A record that a user unlocked a specific prompt. Tracks the prompt, the user (if authenticated), the unlock method (ad, subscription, admin override), and the IP hash.

**Database model:** `UnlockEvent`

### Ad Event

A record of an ad interaction tied to an unlock event. Tracks the ad provider, ad unit, impression ID, completion status, and estimated revenue.

**Database model:** `AdEvent`

### Agent Run

A record of an AI agent execution. Tracks the skill used, input parameters, output, status, timing, and the user who initiated it. Each run can produce one or more PromptDrafts.

**Database model:** `AgentRun`

### Review Decision

A record of a reviewer's judgment on a prompt. Tracks the reviewer, action taken (APPROVED, REJECTED, NEEDS_CHANGES, ESCALATED), and notes. A single prompt can have multiple review decisions over its lifetime.

**Database model:** `ReviewDecision`

### Audit Log

An append-only record of significant actions performed on the platform. Tracks the user, action type, affected prompt, details, and IP address. Used for accountability and debugging.

**Database model:** `AuditLog`

## Status Lifecycle

Prompts follow a defined status lifecycle. The valid transitions are:

```
                    +--> REJECTED
                    |
DRAFT --> PENDING_REVIEW --> APPROVED --> PUBLISHED --> ARCHIVED
                    |                        |
                    +--> NEEDS_CHANGES       +--> DRAFT (unpublish)
                           |
                           +--> DRAFT (author revises, resubmits)
```

### Status Definitions

| Status | Meaning |
|---|---|
| `DRAFT` | Initial state. Prompt is being written or revised. Not visible to the public. |
| `PENDING_REVIEW` | Prompt has been submitted for review. Appears in the review queue. |
| `APPROVED` | A reviewer has approved the prompt. It is eligible for publishing but not yet public. |
| `REJECTED` | A reviewer has rejected the prompt. It will not be published in its current form. Rejection is final -- the content must be substantially reworked. |
| `NEEDS_CHANGES` | A reviewer has requested specific changes. The prompt returns to the author/agent for revision, then can be resubmitted. |
| `PUBLISHED` | An admin has published the prompt. It is visible in the public catalog and available for unlock. |
| `ARCHIVED` | An admin has archived the prompt. It is no longer visible publicly but is retained for reference. |

### Valid Transitions

| From | To | Who | Trigger |
|---|---|---|---|
| DRAFT | PENDING_REVIEW | Author/Agent | Submit for review |
| PENDING_REVIEW | APPROVED | REVIEWER, ADMIN | Approve in review |
| PENDING_REVIEW | REJECTED | REVIEWER, ADMIN | Reject in review |
| PENDING_REVIEW | NEEDS_CHANGES | REVIEWER, ADMIN | Request changes in review |
| NEEDS_CHANGES | DRAFT | Author/Agent | Begin revisions |
| NEEDS_CHANGES | PENDING_REVIEW | Author/Agent | Resubmit after changes |
| APPROVED | PUBLISHED | ADMIN | Publish |
| PUBLISHED | DRAFT | ADMIN | Unpublish |
| PUBLISHED | ARCHIVED | ADMIN | Archive |
| DRAFT | ARCHIVED | ADMIN | Archive unused draft |

## Enum Values

### PromptType

| Value | Meaning |
|---|---|
| `TEXT` | General-purpose text generation prompt |
| `CODE` | Code generation or programming-focused prompt |
| `SYSTEM_PROMPT` | A system instruction meant to configure an AI's behavior |
| `CHAIN` | A multi-step prompt workflow (prompt chaining) |
| `IMAGE` | An image generation prompt (for DALL-E, Midjourney, etc.) |

### UserRole

| Value | Meaning |
|---|---|
| `USER` | Standard user. Can browse and unlock prompts. |
| `REVIEWER` | Can review prompts in the review queue. |
| `ADMIN` | Full access: review, publish, manage users, trigger agents. |

### AgentRunStatus

| Value | Meaning |
|---|---|
| `QUEUED` | Run is waiting to be executed. |
| `RUNNING` | Run is currently in progress. |
| `COMPLETED` | Run finished successfully, drafts generated. |
| `FAILED` | Run encountered an error. |
| `CANCELLED` | Run was cancelled by an admin. |

### ReviewAction

| Value | Meaning |
|---|---|
| `APPROVED` | Reviewer approved the prompt. |
| `REJECTED` | Reviewer rejected the prompt. |
| `NEEDS_CHANGES` | Reviewer requested specific changes. |
| `ESCALATED` | Reviewer flagged for senior review. |
