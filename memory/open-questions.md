## Open

### OQ-001: CDN for Preview Assets

**Question:** Should we use a CDN for serving preview images and other static preview content?

**Context:** Preview content includes rendered text, code snippets, and potentially images. Text and code can be stored in the database, but image previews may benefit from CDN delivery.

**Options:**
- Store everything in the database (simplest, no CDN dependency).
- Use a CDN for images only (S3 + CloudFront, Cloudflare R2).
- Use a CDN for all preview content (more complex, better performance at scale).

**Leaning:** Start with database storage. Add CDN when image previews are introduced.

### OQ-002: Multi-Reviewer Approval

**Question:** Should a prompt require approval from multiple reviewers before it can be published?

**Context:** Currently, a single reviewer approval is sufficient. Multi-reviewer could improve quality but slows the pipeline.

**Options:**
- Single reviewer (current approach, faster pipeline).
- Two reviewers required (higher confidence, slower).
- Configurable per category (sensitive categories require two, others require one).

**Leaning:** Single reviewer for MVP. Revisit if quality issues emerge.

### OQ-003: Subscription Unlock Alternative

**Question:** Should we offer a subscription tier that bypasses the ad unlock flow?

**Context:** Some users may prefer paying a monthly fee to skip ads entirely. This could be a secondary revenue stream.

**Options:**
- Ad-only (current approach, simpler).
- Ad + subscription (two unlock methods, more revenue diversification).
- Ad + one-time purchase per prompt (micro-transactions).

**Leaning:** Defer until ad revenue is proven. Subscription adds significant billing complexity.

### OQ-004: Full-Text Search Engine

**Question:** When should we migrate from PostgreSQL full-text search to a dedicated search engine?

**Context:** ADR-006 chose PostgreSQL FTS for MVP. The trigger is catalog size or search quality feedback.

**Options:**
- Stay with PostgreSQL FTS indefinitely (simplest).
- Migrate to Typesense at 5,000+ prompts (lightweight, easy to deploy).
- Migrate to Elasticsearch at 10,000+ prompts (most powerful, most complex).
- Use Algolia (managed, expensive, lowest maintenance).

**Leaning:** Monitor search quality feedback. Typesense is the likely next step.

### OQ-005: Rate Limiting Strategy

**Question:** What infrastructure should we use for rate limiting?

**Context:** Rate limits are needed for unlock requests, API routes, and abuse prevention.

**Options:**
- In-memory Map (simplest, does not survive server restarts, does not work across multiple server instances).
- Redis (durable, works across instances, adds infrastructure).
- Edge middleware rate limiting (Vercel Edge, Cloudflare Workers).
- Upstash Redis (serverless Redis, works well with Vercel).

**Leaning:** In-memory for MVP (single instance). Upstash Redis when deploying to multi-instance.

### OQ-006: Analytics Platform

**Question:** How should we track and visualize platform analytics (page views, unlock rates, revenue)?

**Context:** Need to track user behavior, content performance, and revenue metrics.

**Options:**
- Build custom analytics dashboard from AuditLog and event tables.
- Use Plausible or Umami for privacy-friendly page analytics.
- Use PostHog for product analytics and feature flags.
- Use Mixpanel for event-based analytics.

**Leaning:** Start with custom queries on existing event tables. Add Plausible for page-level analytics.

### OQ-007: Preview Generation Automation

**Question:** Should preview content be auto-generated by running the prompt, or manually created?

**Context:** Previews currently must be manually attached to prompts. Auto-generation would save time but requires running the prompt against an AI model, which has cost and quality implications.

**Options:**
- Manual only (current approach, highest quality control).
- Auto-generate with manual approval (agent runs the prompt, reviewer approves the preview).
- Auto-generate with auto-approval (fastest, lowest quality control).

**Leaning:** Auto-generate with manual approval. The agent pipeline already exists for this.

### OQ-008: Prompt Versioning UI

**Question:** How should version history be presented to end users?

**Context:** The data model supports versioning, but we have not designed the UI. Users who unlocked an earlier version might want to see what changed.

**Options:**
- Show latest version only (simplest, least confusing).
- Show version list with changelog.
- Show diff view between versions.
- Allow users to access any version they have unlocked.

**Leaning:** Show latest version with a changelog note. Diff view is a future enhancement.
